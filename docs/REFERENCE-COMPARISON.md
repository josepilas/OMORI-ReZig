# C++ console reference and OMORI ReZig

The comparison uses [meetox80/omori at bec8f898](https://github.com/meetox80/omori/tree/bec8f898dfa95239d7eed7f98e0968d1742faf48). Its engine splits RPG Maker state, OMORI-specific scenes, a JavaScript compiler and VM, and hardware backends. A separate builder prepares maps, textures, fonts and movies for each target.

The project-specific C++ code is available for reading under the reference's license. Its RPG Maker MV core and several libraries have separately named terms. This release uses the reference to identify behaviors and testing patterns. ReZig implements the selected features in Zig using its existing engine and runtime data. [Reference license](https://github.com/meetox80/omori/blob/bec8f898dfa95239d7eed7f98e0968d1742faf48/LICENSE)

| Area | Reference design | OMORI ReZig v41 |
| --- | --- | --- |
| Movement | Each follower chases the preceding character and synchronizes on transfer. | Each follower tracks its own destination, facing and glide. Both map render paths draw the trail. Visibility, gathering and save/load carry party state. [Reference player](https://github.com/meetox80/omori/blob/bec8f898dfa95239d7eed7f98e0968d1742faf48/engine/src/rpg/player.cpp) |
| Dialogue | A dedicated message window advances characters, pauses on control codes and hands off to choices. | The message window lays out text once, reveals whole UTF-8 characters, interprets supported wait/pause controls and consumes the reveal input before a choice can accept it. Instant Text is a saved option. [Reference dialogue](https://github.com/meetox80/omori/blob/bec8f898dfa95239d7eed7f98e0968d1742faf48/engine/src/omori/message.cpp) |
| Battle | A command window tracks the active actor and collects each actor's choices before the turn. | Living members can each choose an action and target. B revisits earlier choices, shared item reservations are released when a choice is replaced, and Guard uses the supplied skill and defensive state. [Reference battle scene](https://github.com/meetox80/omori/blob/bec8f898dfa95239d7eed7f98e0968d1742faf48/engine/src/omori/battle_scene.cpp) |
| Field presentation | Pictures have ordered slots, transforms and effect state. Separate systems handle weather and map sprites. | Pictures draw by slot and support mirrored scales, pivoted rotation and additive blending. Field rain, storm and snow have bounded particle counts and fade with the screen state. Visual event routes handle supported frame, turn, wait and sprite changes. [Reference pictures](https://github.com/meetox80/omori/blob/bec8f898dfa95239d7eed7f98e0968d1742faf48/engine/src/omori/spriteset.cpp) |
| Coverage | The reference reports broad map and troop startup coverage on desktop. | A Zig catalog test starts each populated troop and loads each supplied catalog map for both data providers. Input-driven SDL walkthroughs cover the journal, room, recruitment, save/load and a diagnostic battle. [Reference README](https://github.com/meetox80/omori/blob/bec8f898dfa95239d7eed7f98e0968d1742faf48/README.md) |
| Platform support | Per-console rendering, audio, filesystem and video code sits behind a platform layer. | The source release puts the engine and its tests first. Linux and R36S use the SDL2 backend. The porting guide identifies SDL, POSIX and device bindings a future console target needs to replace. [Porting guide](PORTING.md) |

The supplied PC and Android catalogs contain 517 readable maps, 470 with Tiled data, and 337 populated battle troops. Both providers list Map513 without a corresponding map file. Startup coverage measures data loading and battle initialization. Event execution and story progression require separate walkthroughs.

The reference also contains a JavaScript VM, movie playback, richer sprite effects, and more custom menus and minigames. These remain substantial compatibility work in ReZig. Per-actor commands address turn input. Battle presentation, follow-up skills and game-specific battle scripts still need broader coverage.
